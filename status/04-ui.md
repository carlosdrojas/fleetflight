# 04 ui: status

**Screens 1–6 working against `fixtures/`. CI screen (7) skipped on purpose, per the brief.**

## How to run
```sh
cd ui && npm install
npm run dev        # http://localhost:5173, /api answered from ../fixtures (dev middleware in vite.config.ts)
npm run dev:api    # same UI, /api proxied to FF_API (default http://127.0.0.1:8765 = `fleetflight serve`)
npm test           # vitest: lane/segment/window logic + never-crash renders (23 tests)
npm run build      # type-check + bundle to ui/dist/ (gitignored)
```
`fleetflight serve` should host `ui/dist/` as static files. The build uses relative asset paths (`base: "./"`) and hash routing (`#/cex/<id>`), so no SPA fallback route is needed. The UI calls `./api/...` relative to the page.

## Done
- Vite + React 19 + TypeScript, no UI kit. Dark theme, Space Grotesk / IBM Plex Sans / JetBrains Mono, hi-fi colour tokens.
- Renders **only** API payloads: `/api/describe`, `/api/runs`, `/api/runs/<id>`, `/api/cex/<id>`, `POST /api/replay {cex, sut}`. Every field is optional in `src/lib/types.ts`, and every screen has loading, empty and error states. Errors show the server's `{"error": ...}` text, or the status line.
- **MOCK DATA** badge appears only when a payload on the current page (or describe/runs) has `"_fixture": true`.
- **Spec:** components with states and SUT/model owner, injectables (with numeric param bounds), invariants with formula and `bound_ms`, assumptions tagged ASSUMED / OUT OF SCOPE, bounds, constants, SUT versions.
- **Checks:** run strip from `/api/runs`, run detail with stat tiles, per-depth bars from `stats.new_states_per_depth` (counterexample depths in red), and an invariant table linking to counterexamples. Warns when `stats.complete` is false.
- **Counterexample** (the demo screen):
  - Lanes come from `describe.snapshot_keys` where `lane: true`. The fallback is string-valued snapshot keys.
  - Segments group consecutive steps with equal values. The x axis is `t_ms`.
  - Injected moves get ⚡ markers on the lane named by their prefix (`bus_delay` → `bus`), or at the top otherwise.
  - Deadline = `snapshot[timer_key]` + `bound_ms` for the window live at the violating step.
  - The violation hatch runs from the deadline to `violated_at_ms`, on the lanes named in the invariant formula.
  - A timer lane shows the window against its budget.
  - Click a segment or step, or use ←/→/Home/End: the cursor moves and the state panel shows that step's full snapshot, with changed keys marked.
  - Idle ticks fold into "··· N ticks" rows.
  - Also: Download .json.
- **Replay:** pick a SUT from `describe.sut_versions`. Shows the hash banner (checker vs simulator), a per-step ✓/✕ with diff keys, skipped moves, per-invariant results and `violation_window_ms`. **Repeat ×N** fires N `POST /api/replay` calls (4 at a time) and draws the determinism grid from `full_trace_hash`, plus a `uniq -c`-style count.
- **Versions:** replays the counterexample against every `sut_versions` entry in parallel and draws the "fault → stop vs budget" bars from `violation_window_ms` (dashed = `bound_ms`, red = over budget). A failed replay only marks its own row as an error.
- **Regressions:** uses `/api/regress` if it exists (see request below). Otherwise it shows the regression inputs from the counterexample (injected moves with `tick_index`, `ticks`, invariant, expected hash) and the CLI commands, labelled as such.

## CONTRACT REQUEST (for 03 cli / serve)
1. `GET /api/regress` → `{"schema": "fleetflight/regress-list@1", "tests": [{"cex": "cex-…", "path": "tests/regress/test_cex_….py", "invariant": "I1", "sut": "firmware-ref@v0.3.1"}]}`
2. `GET /api/regress/<cex-id>` → `{"cex": "cex-…", "path": "…", "source": "<file contents>"}`. Return 404 if the file hasn't been generated yet.
   Both are read-only file reads of `tests/regress/`. The UI already calls them and falls back cleanly on 404.
3. Please return errors as JSON `{"error": "<message>"}` with a 4xx/5xx status. The UI shows that message.

## Notes for the integrator
- The UI sends `sut` in `POST /api/replay` as the full id from `describe.sut_versions` (e.g. `firmware-ref@v0.3.1`), which the CONTRACT allows.
- Lane colours are picked by the first word of a state value (FAULTED → red, RESTARTING/DEGRADED → amber, ONLINE/HEALTHY → green, DISCHARGING → blue, IDLE/SHUTDOWN → grey). Unknown words fall back to blue. It's styling only; no data is hard-coded.
- `ui/dist/` is gitignored. Build it before `fleetflight serve` (Makefile target suggestion: `cd ui && npm ci && npm run build`).
